## Confirmed issues fixed

- **Storage authorization (high):** live INSERT policy admitted every authenticated account. Existing uploader UPDATE/DELETE policies could change or remove an image used by a historical published revision. Added restrictive boundaries: verified, active staff with applicable MFA, caller-owned upload prefix, no client overwrite/delete, and no anonymous/reader listing. Existing public asset URLs remain functional. Restrictive rules contain existing dashboard policies rather than depending on permissive-policy replacement.
- **Migration drift (high):** live `studio_command` used direct publishing but GitHub replay still required approval. Live implementation also excluded Editor-only users and disabled optional review. A new migration reconciles the approved owner-publishing workflow, Editor/Publisher/Admin oversight, optional independent review, current-version checks and own-article Writer withdrawal. Every action checks the live role/session/email/MFA policy. No changes to Auth internals or account grants.
- **Lost editorial data (high):** Tiptap serialization dropped credit/source metadata and flattened bold/italic, partial links, H3 and numbered lists. Introduced structured inline text and image attributes, a selected-image metadata panel and escaped public rendering. Unknown rich-text nodes that cannot round-trip are disabled. No stored HTML/base64 is introduced.
- **Missing attribution (high):** public article projection omitted image alt/caption/credit/source fields; the renderer hid credits unless a caption existed. Public projection now explicitly includes supported metadata and strips unsupported inline fields, including legacy rows. Captions, credits, source links and rights notes render independently; alt text remains accessibility-only. New review/publication requires alt text and a source/credit/rights record or an explicit internal designation. Existing published revisions are not rewritten.
- **History:** new audit events retain previous/new state as well as actor and revision. Public correction/update notes remain visible after subsequent minor revisions. Material `update` now requires a public note like `correction`. Article removal still uses withdrawal notices, not destructive deletion.
- **Image delivery/request limits:** CSP now permits HTTPS image sources used by the existing upload/URL workflows. Multipart reads are bounded before parsing, supplied MIME types are checked against image signatures, and raw provider errors are not logged. Header checks are not a full image decoder/malware scanner. JSON request bounds now match the 2 MB longform policy. Missing articles return 404; backend failures return 503.
- **Simulation math:** Battery Experience previously copied the mixed-profile runtime into each individual workload. Each workload now uses its own power; the blended runtime is returned separately as `profileRuntimeHours`. `workloadOrder` no longer duplicates or silently drops supplied loads. Numerical version is `0.5.0-battery.2`; previous implementation is available at pre-review commit 98212b3. Public geometry/device engine remains v0.4.0; the v0.5 battery library is not yet integrated into that UI.
- **Verification:** updated obsolete approval-required database tests. Added round-trip, payload-bound, upload-format and mixed-workload regression coverage. Added calibration dataset structural validation to `npm run verify`. Limited test concurrency to two workers after simultaneous PostgreSQL WASM startup exceeded existing 30-second hooks; isolation and assertions remain enabled.
