# ADR-013 — Versioned Virtual Device Models for Simple Mode

Status: Accepted direction; Phase 1 implementation pending review.
Date: 2026-10-04

## Decision

Simple Mode may generate a reusable, AI-led Virtual Device Model covering battery, CPU, GPU/gaming, thermals/sustained operation and charging. AI proposes engineering parameters; separately versioned modules will evaluate them. Phase 1 introduces contracts and validation only. No engines, provider calls, endpoints, persistence migrations or UI behavior are changed.

Unknown parameters, including nominal pack voltage and energy, may be predicted only with sufficient analogous evidence. Predictions require explicit status, a nonzero plausible range, units, confidence, rationale, assumptions, dependencies and revision-bound evidence references. No mAh-to-Wh default voltage is introduced. Unknown remains an explicit valid state without numerical values.

Direct confirmed/measured/reported values must match server-owned evidence for the same subject, quantity, conditions, units, range and status. Provider output contains references, never authoritative citation metadata. Evidence from another phone may support an approved analogy, never become a measurement of the target phone.

Derived values record method/version and dependencies. Predicted lineage propagates transitively; confidence cannot exceed predicted/derived dependencies. Cycles and unknown dependencies are rejected. Deterministic arithmetic does not turn predictions into measurements.

An analogy assessment is a trusted application-policy input, not a provider-issued approval. It binds the exact parameter, evidence revisions, allowed range and maximum confidence. Phase 1 does not implement the assessment process; later evidence policy must determine sufficiency. Simply passing schema validation does not establish engineering accuracy.

## Revisions and reproducibility

Each model has an identity, sequential revision, parent revision, configuration identity/revision, subject, evidence snapshot identity, generation receipt and timestamp. Initial revision is 1. Subsequent revisions append and cannot rewind configuration or time. Validation takes the authoritative prior revision; storage must later enforce atomic compare-and-append and uniqueness. Accepted parsed models are deeply frozen without mutating caller input.

Multiple operating points use distinct parameter IDs and conditions. Future runs bind a model ID/revision and versioned test conditions. Changing device inputs requires a new configuration revision; changing only test conditions reuses the accepted device. Missing parameters do not imply zero or readiness for a category.

## Compatibility

Legacy battery schemas, parsers, provider, API, exports and deterministic/calibration code remain unchanged. The optional adapter maps a new parameter to the existing range/provenance shape; predicted or prediction-derived inputs become `estimated`, never `measured`. Full new lineage remains in the Virtual Device Model and must accompany future run receipts. Confirmed values conservatively map to modeled because the old taxonomy has no confirmed status.

Advanced Mode continues to require explicitly supplied engineering inputs. The new prediction permission does not apply to its calculation path.

## Bounds and limitations

Initial smartphone acceptance bounds are versioned validation policy, not measured calibration or claimed population limits. Values outside them require policy review, not clamping. Protocol/version/workload are mandatory on known parameters; GPU values also require resolution/quality, thermal values require temperature location and charging curve points require state of charge. Battery capacity/voltage/energy explicitly use pack basis to prevent cell/pack ambiguity.

Battery derived energy must cover the capacity-times-voltage interval when those dependencies are supplied. Charging curve power cannot exceed declared peak power. These checks detect contradictions, not full physical feasibility. Future engines must validate their own required parameters, curves, correlation assumptions and energy/thermal accounting.

No paid service is introduced. Existing publication functionality and Advanced Mode remain usable without AI.
